# 모듈 패턴

## 캡슐화와 최소 노출의 원칙(POLE)

> 캡슐화의 목표

- <span class='red'>데이터 + 함수</span> 를 함께 배치해 공통의 목적을 달성하는 것
- 캡슐화된 데이터와 함수의 특정 측면의 <span class='red'>가시성(공개와 비공개의 경계)</span>을 제어하는 것

## 모듈이란 🔖

> 데이터 + 함수(메서드)의 모음
> 모듈에서는 비공개 세부 정보와 공개적으로 접근 가능한 세부 정보(공개 API)를 구분합니다.
> 모듈도 상태를 유지합니다.

---

#### 왜 모듈화 해야하는 것일까? 🤔

> 코드 체계화, 공개와 비공개의 경계, 최소 노출의 원칙을 이용하여 데이터&함수 과다 노출을 피할 수 있어서 높은 품질의 코드를 유지 보수 할 수 있다.

---

## 1. <span class='red'>모듈이 아닌</span> 다른 유용한 코드

### 1-1 네임 스페이스 (무상태 그룹화) - 데이터 없는 경우

> 데이터 없이 관련된 함수를 그룹으로 묶는 것을 네임스페이스(namespace)라고 부릅니다.

```
var Utils = {
    cancel(evt){
        evt.preventDefault();
        evt.stopPropagation();
    },
    wait(ms){
        return new Promise(function c(res){
            setTimeout(res,ms)
        });
    },
    ...
}
```

---

### 데이터 구조(상태 유지 그룹화) - 데이터의 가시성 제한 하지 않는 경우

```
var student = {
    records : [
        {id : 14, name :"abc" , grade:99}
    ],
    getName(id){
        var _student = this.records.find((obj)=> obj.id === id);
        return _student.name;
    }
};

student.getName(14) // abc
```

> records는 공개적 접근 가능하기 때문에 모듈이 아닙니다.
> 데이터와 함수를 모아놓았다는 측면에서는 캡슐화과 관련이 있지만 가시성 통제 측면에서는 아닙니다.

## 2. 모듈인 코드

### 모듈 (상태를 가진 접근 제어)

```
var student =(function defineStudent() {
    var records = [
        {id : 14, name :"abc" , grade:99}
    ];

    var publicAPI = {
        getName
    };
    return publicAPI;

    ...

    function getName(id){
        var _student = this.records.find((obj)=> obj.id === id);
        return _student.name;
    }
})();

student.getName(14) // abc
```

---

코드 작동 방식

- defineStudent()라는 IIFE가 실행되면서 생성
- IIFE는 내부 함수 getName()을 참조하는 프로퍼티를 가진 publicAPI 객체를 반환
- student.getName(14)은 공개 API를 통해 노출된 내부 함수를 호출 하고, 클로저를 통해 내부 변수 records에 접근
- 클래식 모듈 패턴에서는 함수를 직접 반환 하면 됩니다.

<details>
<summary> 클래식 모듈 정의</summary>

1. 적어도 한 번 이상 실행되는 모듈 팩토리 함수가 외부 스코프에 존재해야 합니다.
2. 모듈의 내부 스코프에는 해당 모듈의 상태를 나타내는 정보가 최소한 하나 이상 있어야 하며, 이는 외부에서 접근 할 수 없어야 합니다.
3. 모듈은 하나 이상의 함수를 공개 API로 반환해야 합니다. 이 함수는 내부 스코프의 숨겨진 상태를 클로저를 통해 보존, 관리 합니다.
</details>

### CommonJS & ES 모듈

공통점

- 파일 기반
- 기본적으로 바깥 코드에 대해 비공개

차이점

- ESM은 파일 상단에 전처리 구문 'use strict'가 없어도 엄격모드로 실행

---

- 모듈 정의
  - CommonJS (require(파일의 전체 공개 API가 불러와짐), module.exports)
  - ESM (import, export)
    - export function getName() -> 기명 내보내기
    - export default function getName() -> 기본 내보내기
    - import {getName} from ''
    - import {getName as getStudentName} from ''
    - import getName from '' -> 기본 내보내기 시 가능
    - import {default as getName , 기명 내보내기} from ''
    - import \* as Student from '' -> Student.getName(14);
